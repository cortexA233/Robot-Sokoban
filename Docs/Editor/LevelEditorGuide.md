# 关卡编辑器使用说明

环境：Unity 2022.3.51f1、URP 14.0.11。入口：**Sokoban_Tools > Level Editor**。

窗口按文件、编辑、校验与试玩、目录与帮助分组，现场编辑工具默认折叠。左侧画笔分为工具、地形、角色与箱子、机关；示例关卡在可展开的“示例关卡”中。第一次编辑可打开 L04 或 LAB01。当前简化与覆盖规则见 [v0.4.1 实现记录](../Versions/V0.4.1EditorSimplification.md)，基础迭代验收见 [v0.4.0](../Versions/V0.4.0.md)，完整交付范围另见 GDD 第 6/11 节。

可撤销 GM 与 Play Mode 现场编辑的行为约定见 [GM 与关卡编辑器现场试玩迭代方案](../Debug/GMAndLiveEditingPlan.md)。当前操作方式见下文，验证范围见 [实现记录](../ImplementationProgress.md)。

## 从空白关卡开始

1. 点击“新建”。默认地图 9×9；展开右侧“关卡属性与尺寸”，设置宽高（5–32）并点击“应用尺寸”。点击“一键生成边界墙”可封闭边界。
2. 核对关卡 ID 和尺寸，再开始布置。v0.6.0 已取消标题、目标提示、完成文案配置；运行时用关卡顺序号识别，作者工具显示稳定 ID。
3. 选择左侧画笔，在窗口内的二维棋盘或 SceneView 网格上左键绘制。地图左下角为 `(0,0)`，上方为北 `+Z`；P 是玩家，C 是能源箱，X 是普通箱，◎ 是目标插槽，s 是辅助插槽，D 是门，箭头表示固定转向板。
4. 放一个玩家、至少一个目标插槽、足够数量的能源箱。普通箱可以推动，但不供电、无需归位，不计入能源箱数量。选中箱子后可在右侧“箱子类型”中修改，修改支持撤销。可以先做玩家 `(1,3)`、能源箱 `(2,3)`、目标 `(6,3)` 的 9×7 小图。
5. 将 `(3,3)`、`(4,3)`、`(5,3)` 涂成低摩擦轨道。插槽和门只能放在普通地板上。
6. 在 `(7,3)` 放门。选择该门，在右侧设置朝向、Any/All，并勾选 `(6,3)` 的目标插槽。SceneView 中可以看到插槽到门的连线。
7. 点击“校验”，或直接点击“试玩并录制”。直接试玩也会校验当前工作副本并刷新完整问题列表；错误阻止试玩，提示/警告允许试玩。窗口右侧临时提示约 6 秒后自动消失，也可手动关闭，底部完整列表继续保留。点击带坐标的问题定位该格；修改内容后旧结果标为需要重新校验。“结构合法”不代表关卡一定有解。

## 选择格子与格内对象

- 顶部状态条持续显示选择/画笔模式和放置朝向；当前画笔带勾选标记。按 Esc 或点击左侧“选择”返回选择模式。
- 选择模式下点击其他格，会一起更新高亮格、格内对象列表和属性目标。空格显示地形并清除旧对象；有对象时优先选玩家或箱子，再选机关。纯选择不修改关卡、不产生编辑撤销。
- 同一格可有地形、机关和角色/箱子。箱子压在插槽上时，二维符号同时显示箱子与插槽；右侧通过“能源箱 / 目标插槽”等可读按钮切换，当前对象带 ✓。玩家也在同格列表中。
- 点击右侧对象按钮会进入选择模式；再次点击同一格保留当前选中的对象。选择其他格会重新按该格内容选择，属性不会继续指向旧格。
- 坐标、箱型、朝向和“删除选中元素”作用于当前对象。移动箱子不带走下面的插槽。放置模式允许连续绘制；同层放置会替换已有对象，箱子和插槽等合法叠放保留。

“场景内相机聚焦”会让 Unity 的 Scene 窗口重新对准地图中心；不改变玩家镜头或对象位置。机关覆盖仍要求普通地板，作者玩家出生点不能位于门格；非法放置保留原布局。不同机关覆盖导致插槽被移除时，其供电引用会同步移除，可整次撤销。

## 添加固定转向板

1. 选择左侧“固定转向板”，在“朝向”选择 N/E/S/W，放在普通地板上。已有插槽或门会被替换，箱子保留；SceneView 悬停显示放置方向。
2. 选中后在右侧修改“朝向”，或按 Q/E 旋转。箱子覆盖板时，二维格子仍显示方向；游戏内板边有方向标记。
3. 可以连接低摩擦轨道，但板与轨道不能占同一格。两类箱子入板后沿箭头继续，机器人正常行走；受阻停稳后不会自行重启，需再次推动。
4. 先试左侧 L07/L08，再查看 L09–L12。修改方向后重新试玩通关并录制解法；保存、另存副本、草稿恢复、缩图和现场编辑均保留板方向。

## 编辑与工作保护

- 左键选择/放置；地形支持连续拖刷。同层物体直接覆盖：两类箱子互换、玩家/箱子互换、机关互换。原位更新箱型、插槽目标身份、门或转向板朝向时保留 ID；插槽身份变化保留供电引用。用地板/墙/虚空/轨道画笔修改地形；清空单个物体用右侧“删除选中元素”。右键不再修改关卡。
- 涂 Wall/Void 会删除该格的实体和相关供电引用；一组拖刷可一次撤销。删除插槽会同步移除门引用，若来源为空，校验会报错。
- 选择格子后，可在右侧选择该格的不同层实体，输入 X/Z 后点击“移动到坐标”，或修改朝向、目标属性与门来源。Q/E 旋转所选玩家/门/转向板或后续放置朝向。
- Ctrl+Z/Ctrl+Y 撤销重做；Ctrl+S 保存。SceneView 的 Alt 与中键保留原生导航。
- 缩图前显示越界元素数并确认；扩图新增区域为 Void。尺寸修改可撤销。
- 未保存状态与当前路径显示在窗口底部。未保存草稿备份在 `Library/SokobanDrafts/Current.json`，重开窗口/脚本重载后恢复；撤销栈仅保证当前编辑会话。
- 保存采用同目录临时文件再替换目标。短暂文件占用会重试；最终失败在窗口提示，原目标不会先被删除。打开其他文件或关闭窗口时有保存/放弃/取消处理。
- “另存为副本”生成新的关卡 ID；副本选择不同文件名。解法跟随复制，但须重新试玩通关并录制，才能建立新版本证明。

## 试玩、录制与返回

1. 点击“试玩并录制”。工具先显示当前校验结果，通过后保存独立试玩快照，再通过 `playModeStartScene` 进入 Bootstrap。未保存内容可以直接试玩；Unity 会按原生流程处理其他场景的未保存内容。
2. 游戏默认俯视。方向键↑→↓←分别为 N/E/S/W；WASD 根据镜头方向映射；V 在俯视与第三人称之间切换；鼠标环绕，滚轮缩放；Z 撤销；R 重开；Esc 暂停。
3. 上面的低摩擦小图只需按一次右方向键。玩家进入 `(2,3)`，箱子滑到 `(6,3)`，计数为 1 步/1 推。动作中 Z/R 也可取消整次表现。
4. 通关后点击“保存为参考解法”。随后退出 Unity Play Mode，原场景与原始作者摆放恢复；参考解法进入工作副本，需点击“保存”写入文件。
5. v0.4.1 已删除手动“回放解法”功能。修改关卡会使原证明过期，需重新试玩通关、保存参考解法并保存关卡。目录和构建仍自动校验录制指令、终点、计数和当前内容哈希。

编辑器试玩不保存正式玩家进度，也不显示“下一关”或运行时选关，以便保持作者副本与正式流程隔离。直接打开 Bootstrap Play 时，游戏读取 CampaignCatalog，支持通关后下一关、返回选关与暂停选关。目录资源在 `Assets/Resources/configs/CampaignCatalog.asset`，2026-09-18 当前工作区顺序为 L04→L06→L07→L08→L10→L11→L12，共七关；目录顺序可由作者调整，历史九关验收记录保持原样。

## 正式关卡目录与构建校验

1. 保存关卡与参考解法，保证解法对应当前内容。点击顶栏“关卡目录”，或使用 **Sokoban_Tools > Campaign Catalog**。
2. 点击“使用当前作者关卡”，或将关卡 JSON 拖入“加入关卡 JSON”字段，然后“加入目录”。未保存、结构不合法、重复 ID、参考解法缺失/过期/验证失败时，加入会被拒绝并显示原因。
3. 用 ↑ / ↓ 排序，“移出”只删除目录引用，保留关卡 JSON 与解法文件。操作支持撤销/重做；最后点击“保存目录”。目录的未保存标记独立于作者文档。
4. 每行显示顺序号、ID、结构和解法状态；“打开”进入作者文档。下方问题列表可打开对应关卡并定位坐标，缺失资源则定位 Project 资源。Play Mode 中目录只读。
5. 点击“校验目录与构建资源”检查所有正式条目，以及 Bootstrap、玩家 Prefab、正式 UI、空间站主题的必需资源。每次 Unity Player 构建也会自动执行同一检查；坏关卡、空目录、缺失引用、重复 ID、过期或不正确的解法会阻止构建，不会悄悄跳过。

游戏选关和“下一关”直接采用目录顺序。`test_levels` 下的开发关不会自动加入，显式加入后会标注开发测试身份。目录移出不承诺从 Player 包中排除仍放在 `Resources` 下的文件；最终数据筛选原归 v0.9.0，现随该版取消，保留为已知限制。

## 运行时 GM

GM 是运行中的调试工作台，用来摆局面、检查供电和定位问题。**Unity Editor 的 Play Mode 或 Development Build 中按 F1 开关**；非开发构建不提供入口。在 Editor 中先让 Game 视图获得键盘焦点。F1 显示已有页面，不需要生成或保存资产。

### 打开、收起与显示设置

- 面板打开时占用游戏输入并释放鼠标；方向键、Z/R/V 和底层游戏按钮不会穿透操作。要撤销、重开或换视角，使用 GM 底部对应按钮。打开 GM 本身不会暂停已经开始的动作动画，也不会打开正式暂停菜单。
- **Esc**：正在点选时先取消点选，再按一次关闭 GM；未点选时直接关闭。也可按 F1 或点“关闭”。关闭后释放先前按住的方向键，再重新按下移动。
- **监视**：切换监视开关并收起面板，开启时保留关卡 ID、玩家坐标、目标供电数和动作状态条，可以继续游戏；F1 重新打开后再点“监视”可关闭状态条。
- 拖标题移动面板；“字− / 字+”调整字号；“面板宽度”滑条调整宽度。内容超出时在中间区域滚动，底部常用按钮保持可见。
- 搜索框按分类名或页面文字筛选整块内容，不是指令控制台；可能同时显示多个分类。切换标签前清空搜索，可恢复一次只看一个分类。

### 四个分类

| 页面 | 用途与操作 |
| --- | --- |
| 关卡 | 查看当前 ID、正式/作者/现场试玩身份和箱子数量；输入目录中的序号并点“进入关卡”。这是从 1 开始的目录顺序号，不是 `Lxx` 中的数字。作者试玩和现场模式不可用运行时选关。 |
| 局面 | 选择玩家或现有箱子，设置坐标、点选格子、移位、交换位置和修改玩家朝向；查看逻辑位置、撤销数量、动画与参考解法状态。 |
| 机关 | 只读检查每个插槽的目标/辅助身份、占据者和供电；查看每扇门的来源及开门原因。这里没有强制通电或直接开门按钮。 |
| 诊断 | 查看输入占用原因与最近操作记录；点“复制完整诊断快照”将 JSON 放到系统剪贴板，可粘贴到文本文件或发给排查问题的人。 |

当前目录为七关：`1=L04、2=L06、3=L07、4=L08、5=L10、6=L11、7=L12`。输入框的“序号 1–6”是旧占位提示；实际范围按运行时加载的 CampaignCatalog 数量检查，以当前目录为准。

### 移动玩家或箱子

1. 在“局面”第一个下拉框选择对象。箱子显示 ID 和“能源箱/普通箱”，场景中的箭头指示所选对象；选择对象时 X/Z 自动填入其当前位置。
2. 用下面任一方式指定目标：直接输入整数 X/Z；或点“点选格子”，再左键点击面板外、没有 UI 遮挡的棋盘格。点选**只填写坐标**，还未移动对象。
3. 点 **“移动到此格”**。底部显示“已应用，可撤销”，或显示目标非法/占格重叠等原因。若面板挡住目标，先拖开面板；俯视更便于选格。
4. 按 F1 关闭面板继续游戏，或点底部“撤销”恢复刚才的位置。

坐标从 0 开始；X 是东西方向，Z 是南北方向，N 为 Z+、E 为 X+、S 为 Z−、W 为 X−。可开“网格”查看，俯视时格子会显示 X,Z；不要把 Z 当成高度，也不要将镜头旋转后的屏幕上下当作固定北南。

移位可跨墙、关闭的门和任意距离，不要求可达路线，不执行沿途推动或滑行。最终落点必须在地图内、不是墙/虚空，且不能和玩家或其他箱子重叠；门格允许落位并触发占据保护。放到轨道或转向板上不会立即自动运输，后续正常推动才使用对应规则。供电与完成状态会立即按新局面重算。

**交换位置**：第一个下拉框选对象 A，下方交换区域的第二个下拉框选对象 B，再点“交换位置”。可交换玩家与箱子，或两只箱子；一次撤销还原整个交换，箱子的 ID 和箱型保持不变。普通移位不能落到已有对象上，需要对调时使用这个按钮。

**修改玩家朝向**：选择 N/E/S/W，再点“修改玩家朝向”。它始终修改玩家朝向，与第一个下拉框当前选的是谁无关。

### 撤销、重开与动画暂停

- **撤销**与关闭面板后的 Z 共用同一条历史。普通移动 A → GM 移位 B → 普通移动 C，连续撤销依次退回 C、B、A；运行时没有重做。GM 移位、交换和改朝向不增加或清零步数/推动数，失败或无变化不产生历史。
- **重开**清空当前玩法历史和计数，恢复当前试玩起点：普通关卡回原起点，现场试玩回最近一次“应用并继续试玩”的起点。
- **切换视角**在俯视与第三人称之间切换，便于查看或点选。
- **暂停动作动画**独立于正式暂停菜单，关闭 GM 后仍生效，并阻止新的移动。若关了 GM 仍无法走动，重新打开并取消该勾选，同时确认已退出现场编辑/正式暂停状态。
- 动作动画过程中进行 GM 操作，以已经提交的逻辑终点为准，取消旧动画并对齐模型；页面的“逻辑玩家”可能先于正在播放的模型位置到达终点。

只打开/查看 GM 不会使参考解法失效。实际移位、交换或改朝向后，页面显示“调试起点/GM 修改，不可保存”，此状态下通关不写正式成绩，也不能保存原关卡参考解法。将所有 GM 修改撤销回去，或在普通关卡重开，可恢复原起点的录制资格；现场起点仍属于调试试玩。

### 检查供电与导出问题现场

- **网格**显示格线，俯视时同时显示坐标；**ID/箱型**显示实体标识，`E` 为能源箱、`C` 为普通箱；**连接线**显示插槽到门的配置连接。它们只改变显示，关闭 GM 后仍可保留，需回到面板取消勾选来隐藏。
- “机关”页中，能源箱占插槽才供电；普通箱或玩家占插槽不供电。`[目标]` 参与通关，`[辅助]` 用于供电但不计通关目标。
- 门的 `Any` 表示任一来源插槽通电即可，`All` 表示全部来源通电；“未通电 · 占据保护打开”表示玩家或箱子站在门格上，为避免夹住对象而保持打开，不代表电路通了。
- 调试门时，选能源箱移到所需插槽 → 到“机关”页看来源与开门原因 → 撤销检查断电后变化。没有开门时先区分箱型、来源关系和 Any/All。
- “复制完整诊断快照”包含关卡定义、局面/箱型/朝向、步推数、移动指令、参考解法资格、会话标识与最近日志；当前只导出文本，不提供快照导入、自动复现、逐帧播放或单步执行。

### 增删箱子与现场编辑入口

这部分只在 Unity Editor 使用。关卡页点 **“现场编辑当前局面（Editor）”**，会打开 Level Editor 的临时现场草稿，可以改地形、箱型、机关连接等。局面页的 **“+ 能源箱 / + 普通箱”** 使用当前 X/Z 增箱；**“删除箱子”** 删除第一个下拉框选中的箱子，不能删玩家。这几个快捷按钮也会进入现场草稿，不是直接执行可由游戏 Z 撤销的移位。

检查草稿后点 **“应用并继续试玩”** 才更新运行中棋盘。此操作建立新起点，步推数归零、玩法撤销历史清空；Z 不能跨回应用之前。要回到首次进入现场编辑前的原局面，用关卡页的 **“结束现场试玩 · 返回原局面”**，不是“重开”。仅应用草稿不会覆盖原关卡文件；要保留为关卡需明确另存副本或带回作者文档后保存。详细步骤见下节。

GM 布局资产为 `Assets/Resources/UI_prefabs/screens/GM/Gm.prefab`。维护代码 `GmUIAssetBuilder.Build()` 可重建它并覆盖手工布局；当前菜单注册已注释，日常使用 F1 不依赖此重建方法。

## 现场编辑并继续试玩

此功能在 Unity Editor 中使用。原作者文档、原关卡文件与临时现场草稿彼此独立。

1. 进入关卡，在 GM 的关卡页点击“现场编辑当前局面”，或在 Level Editor 点击“捕获当前游戏局面”。正在播放的动作对齐已提交的逻辑终点，再进入编辑。
2. 窗口显示“临时现场草稿”，游戏输入被占用。使用原有画笔、坐标属性、箱型控件、机关连接和尺寸工具编辑。Ctrl+Z/Ctrl+Y 只操作草稿。
3. 点击“应用并继续试玩”。错误会显示并保留旧棋盘；通过后创建新的规则与棋盘，从当前摆放重新计数，清空玩法撤销历史。回到 Game View 即可继续，不需退出 Play Mode。
4. R 恢复最近应用的现场起点；Z 只撤销这个起点之后的普通移动和 GM 移位，不跨越结构应用边界。修改箱型也属于结构应用。
5. 再次编辑可以选择“编辑已有现场草稿”，或重新捕获游戏中的最新位置。有未应用修改时，重新捕获会提供继续编辑、取消、替换的选择；旧草稿备份保留。
6. 点击“结束现场试玩”恢复首次捕获前的运行局面、撤销历史、相机、暂停状态与会话身份，并切回原作者文档。

GM 的“+能源箱”“+普通箱”“删除箱子”是现场草稿的快捷入口；检查修改后点击应用。普通箱不足以补充能源数量。现场模式可测试能源不足的局面，也允许玩家站在门格；转为作者关卡时仍执行正式出生点与能源数量校验。

保存操作有三种不同作用：

- **保存 / Ctrl+S**：备份临时现场草稿，不覆盖原 JSON。备份位于 `Library/SokobanDrafts/Live/`，最新工作区索引为 `Workspace.json`。
- **另存为副本**：通过正式校验后输出新 ID 的关卡文件，不自动生成参考解法或加入正式目录。
- **带回作者文档**：通过正式校验与原文档版本检查后，作为一次可撤销作者编辑带回，仍需在作者模式保存。原文档已变化或不是同一关卡时拒绝覆盖，可以另存副本。

关闭窗口会解除编辑输入占用并备份草稿。停止 Play Mode 后可通过“恢复/查看现场草稿”继续处理数据；脚本域重载后若原运行会话无法重连，草稿保持脱离状态，不自动应用到其他关卡。此时退出并重新进入 Play Mode，再捕获新的活动局面。跨域重载不保证保留编辑撤销栈。

旧 v1/v2 关卡仅捕获不会自动升级；增加普通箱时至少升级到 v2，增加转向板时升级到 v3，该编辑可整体撤销。箱型修改使原参考解法过期。现场快照回放和动画逐步检查属于后续 M4，本轮只提供诊断快照导出。

## 数据和示例

- 正式 JSON：`Assets/Resources/configs/levels/L04.json` 至 `L12.json`；L04–L06 为普通箱关卡，L07–L12 为转向运输关卡，均可从左侧示例按钮打开。
- 新图使用 schemaVersion=3，箱型和转向板方向随保存/打开、副本和草稿恢复保留。v1/v2/v3 的旧标题、目标提示和完成文案在读取时兼容丢弃，后续保存不再写出；其余未知字段仍严格拒绝。旧参考解法因规范化内容变化会过期，必须实际回放/录制后重新生成证明。旧版关卡按能源箱读取，加入普通箱时自动升级；改箱型会使原参考解法过期，需要重新试玩通关并录制。
- 实验关：`Assets/Resources/configs/test_levels/LAB01_LowFriction.json`。
- 解法：`Assets/Resources/configs/solutions/*.solution.json`。
- 可重新导入的作者配方：`Docs/LevelRecipes/*.json`。窗口“导入配方”与 `Tools > Sokoban > Import Design Recipes` 使用相同作者操作；批量入口不会覆盖已有文件。
- 运行时只读统一关卡 JSON；不读取配方或 Markdown。
- PlayerActor 包装现有 Robot，动画仍来自现有 FBX。不要为了重建关卡执行会重导出资产的机器人流水线。
