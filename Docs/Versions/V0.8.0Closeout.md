2026-09-18 用户明确要求将选关简化列入新的 v0.8.0 收尾版本，随后追加删除已注释 MenuItem 对应的不必要编辑器工具，以及 F1 GM 页面简化与现场编辑入口改进。本计划采用指定编号；[旧 v0.8.0 引导与难度计划](V0.8.0.md) 继续保持已取消，单独保留历史，不恢复 R07。当前仅登记下述收尾需求，新增范围须另行明确。

## 目标与范围

### R11 · 选关状态简化

依据本次选关界面截图和用户反馈，简化每行关卡状态及页头提示，减少玩家需要阅读的信息。

| 选关状态 | 本版目标显示 |
| --- | --- |
| 当前关卡版本没有有效完成记录（含首次游玩、未完成、仅有旧版本成绩） | 状态区域留空，不显示占位符、“待完成”或“关卡已更新” |
| 当前关卡版本已有有效完成记录 | `已完成 · N 步`，N 取该关当前有效的最佳成绩步数，例如 `已完成 · 10 步` |
| 页头进度汇总 | 保留 `X / Y 已完成`，删除后面的分隔符和“所有关卡均可选择” |

- 选关行不再显示推动次数，删除原有的 `/ N 推`。空状态下仍保留关卡名称、行对齐、点击区域和选中反馈。
- 只调整选关界面呈现。继续保留全关可选、完成数量统计、有效成绩判定和存档中的步数/推动数；不修改最佳成绩比较规则，不清空旧存档。关卡内容变化后，旧成绩仍不计作新版完成，只是不再向玩家显示更新提示。
- HUD、结算、操作说明、作者工具和 GM 中的计数或说明不在本次范围；不扩展为全局删除推动统计。
- 技术依赖为已完成的 v0.6.0 进度/UI 与 v0.7.1 菜单基线。可在现有基线上独立实施，v0.7.0 音频余项继续归原版；旧 R07 引导/难度和 R09 完整交付验收不并入本收尾版本。

### R13 · F1 GM 页面简化与现场编辑入口

将 GM 收敛为关卡入口与当前局面的快速移动工具，完整关卡编辑统一在 Level Editor 完成。本项是用户明确追加的页面改版，与 R11 的选关显示范围分别记录。

#### 页面与控件删减

| 项目 | 本版目标 |
| --- | --- |
| 分类页 | 删除“诊断”“机关”分页、内容与搜索结果入口，只保留“关卡”“局面” |
| 监视 | 删除顶部“监视”按钮、收起后的状态条及其独立刷新/显示状态 |
| 箱子结构编辑 | 删除“+ 能源箱”“+ 普通箱”“删除箱子”及配套提示；增删、改箱型等统一通过现场编辑 |
| 其他对象操作 | 按用户后续确认删除“交换位置”“修改玩家朝向”及对应下拉/绑定；局面页仅保留选中与移动 |
| 动画调试 | 删除“稳定/播放中”等动画状态文案、“暂停动作动画”开关及其专用调试暂停状态；不删除正常游戏动画或正式暂停功能 |
| 参考解法状态 | 删除 GM 上的“参考解法有效/不可保存”等状态显示；底层录制有效性、正式成绩隔离和撤销恢复规则继续执行 |
| 诊断操作 | 随诊断页删除日志面板、输入占用诊断显示及“复制完整诊断快照”按钮；专用无调用实现按依赖核对后清理 |
| 基础操作 | 保留 F1/Esc/关闭、关卡跳转、结束现场试玩、撤销、重开、切换视角，以及未被本次要求删除的搜索/布局和叠加显示设置；删除内容后收拢布局，无空行或空分页 |

#### 现场编辑入口与文案

两处文案严格采用用户指定文本：

| 原文案 | 新文案 |
| --- | --- |
| 现场编辑当前局面（Editor） | **现场编辑（打开关卡编辑器）** |
| 结构修改建立新试玩起点；原关卡文件保留。 | **编辑关卡后请在关卡编辑器内保存变更或保存为新副本** |

- 在 Unity Play Mode 点击该入口后，捕获当前运行局面，打开或聚焦已有的 Level Editor，显示现场草稿，并自动展开顶部 **“现场编辑” Foldout**，使“应用并继续试玩”“结束现场试玩”等操作可见。不能仅打开窗口而保持该组收起，也不要求用户重复捕获。
- 覆盖窗口原先未打开、已经打开、现场编辑组曾手动折叠及布局刷新后的情况；通过 GM 再次进入时应主动展开，不被 `viewDataKey=live-tools` 的旧折叠状态覆盖。日常作者模式不必永久强制展开。
- 已有未应用草稿时继续沿用保护与选择流程；选择继续已有草稿或成功重新捕获后都展开并聚焦。取消、无有效关卡或捕获失败时不覆盖原草稿，不假装已进入成功。
- 该入口仍仅在 Unity Editor 可完成编辑；独立开发版不显示可点击却无效果的入口，F1 的其他保留能力继续可用，非开发版仍不提供 GM。
- 新提示用于引导保存，不改变现有现场草稿、应用、另存副本与带回作者文档的保护规则；不能因替换文案自动覆盖原 JSON。实施时同步作者指南中的保存步骤，明确现场应用与持久化保存各自作用。

#### 选择格子与移动对象

- **用户明确要求：** 在棋盘选中某格后，移动对象自动取该格上的对象；不能仍固定或默认操作玩家。点箱子所在格即选该箱子，点玩家所在格即选玩家，选择信息和场景标记立即同步。
- 移动范围沿用运行时的玩家、能源箱、普通箱。箱子与插槽/转向板同格时选择可移动箱子；地形、插槽、门、转向板自身的修改交给现场编辑。空格或只有静态机关的格子没有可移动对象，应清空旧选择并禁用移动，不能沿用旧对象误操作。
- **用户已确认的交互：** “局面”只保留选中对象信息、目标 X/Z 和“移动到此格”；点选棋盘负责选择源对象，目标坐标独立填写，再点击按钮提交。旧的对象下拉框改为当前选择信息，旧“点选格子”目标拾取入口删除，避免把源对象选择与目标坐标混在一起。交换位置和修改朝向一并删除，其他编辑交给关卡编辑器。
- 选择格子不执行移动、不增加撤销历史；提交时重新确认源对象在当前会话仍有效。切关/重开/结束或应用现场草稿后重置选择；撤销后刷新所选对象的位置，失效 ID 不回退为玩家。
- 点选和按钮交互继续屏蔽底层移动、暂停、镜头与 HUD 输入；F1/Esc 关闭后正常恢复操作。移动沿用合法落点检查、统一撤销、步推数保持及供电/完成重算，不引入拖拽移动或结构编辑。

## 验收计划

1. Unity 编译与 Console 检查；运行受影响的 UI/进度专项检查，覆盖无记录、未完成、有效完成、仅有旧版本成绩。每行状态严格为空或 `已完成 · N 步`，N 与当前有效最佳记录一致。
2. 确认选关页不出现“待完成”“关卡已更新”、推动次数和“所有关卡均可选择”；页头完成数量正确，无残余分隔符。用新存档与已有存档检查进入页面、完成后返回和重启恢复。
3. 在 720p/1080p 查看选关页：空状态与完成状态对齐、无溢出，选中高亮、鼠标点击、键盘导航、滚动、进入与返回均可用，全部关卡仍可选择。
4. 核对当前有效成绩与旧成绩判定、存档数据及 HUD/结算行为保持原规则；验证现有 Prefab 直接编辑后可保存、重开并在运行时正确加载，UI/GM 均不依赖已删除的生成器。
5. 对照 R12 的 10 项清单核对入口、工具专用实现、自动触发和遗留引用已清理；删除目录窗口后的编辑器无残留按钮/空分组。核对保留菜单、共享辅助代码、`.meta`、GUID 与现有资源完整性；Unity 重载/编译与 Console 无新增错误。
6. 运行受影响的作者工具、配方导入、UI/GM、资源和构建校验测试，实际走通关卡编辑/导入/保存/试玩及 F1 工作台；验证占据取证保留入口及调用链可用。运行现有正式目录/参考解法校验及针对本次清理的 Windows 构建、Player 启动/选关检查，不扩展为已取消的完整交付验收。
7. GM 只保留关卡/局面分类；Prefab 与运行时均无诊断/机关页、监视、箱子增删、动画调试或参考解法状态，也无搜索命中、绑定异常或空布局。验证两处指定文案逐字一致，在 720p/1080p 及字号/宽度调整后可读、不截断，现有 Prefab 保存/重开/运行加载正常。
8. 从 GM 实际点击现场编辑入口，覆盖编辑器窗口关闭/已打开、Foldout 已折叠、重复进入及已有未应用草稿的继续/替换/取消；成功时直接显示草稿并展开现场编辑组，失败/取消时保护原文档。走通修改、应用继续、保存草稿/另存副本和结束恢复原局面的保留流程。
9. 按已确认的“点格选对象 → 填目标 X/Z → 点移动”流程，分别点玩家/能源箱/普通箱、空格、墙、仅有静态机关的格子，以及箱子与插槽/转向板同格；实际移动必须作用于所选实体而非默认玩家。确认交换/朝向和旧目标点选入口已删除。覆盖目标越界/墙/虚空/占格拒绝、原位无变化、门格占据保护、箱型/ID 保持、供电与完成重算、计数和混合撤销。选择动作本身不提交玩法变更。
10. 覆盖切关、重开、撤销、现场应用/结束后的选择同步，F1/Esc、UI 遮挡点选与输入不穿透。删除动画调试后正常动画、正式暂停/继续和现场编辑输入隔离仍可用，无残留调试暂停；GM 修改的参考解法/正式成绩限制继续生效，不能因隐藏状态而失去保护。
11. 更新并运行受影响的 GM PlayMode 与现场编辑 EditMode 检查，在 Unity 实机验证按钮、选格及 Foldout 展开；开发版检查保留 GM 功能与 Editor 入口隔离，非开发版确认无 GM 入口/缺失脚本。与 R12 的构建和保留流程检查合并取证，避免重复或扩展为已取消的完整交付验收。
