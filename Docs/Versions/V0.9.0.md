## 目标与范围

- 前置：[v0.4.0](V0.4.0.md)、[v0.5.0](V0.5.0.md)、[v0.6.0](V0.6.0.md)、[v0.7.0](V0.7.0.md)、[v0.8.0](V0.8.0.md) 各自完成验收。统一核对游戏与关卡编辑器的完整交付，不用本轮代替前序版本的功能验证。
- 按 [GDD](../Gameplay/GameDesign.md) 第 11–12 节核对完整要求和 E01–E12，从实际编辑器界面完成创建、编辑、机关配置、校验定位、保存/重载、试玩录制、参考解法、复制及目录管理。
- 在 Windows 非开发 Player 中验证实际交互与至少两关独立通关，覆盖菜单、视角、暂停、撤销/重开、进度重启恢复、音效/BGM/静音及设置保存；正式目录全部参考解法仍需通过。
- 检查正式构建数据、开发工具隔离、关键分辨率和性能，整理工程使用说明、作者指南、构建入口、版本范围、证据及已知限制；修复验收发现的阻断缺陷并复验受影响流程。
- 开工时固定验收机器、性能指标、实际试玩关卡/路径和证据格式。核对 v0.2.1 的受阻记录与后续版本覆盖关系，只有明确证据才能补充其收尾说明，保留原历史结果。
- 本版不加入新玩法或大规模表现重做，不自动标为 v1.0.0，不修改 PlayerSettings 版本、创建标签、上传构建或发布。若 GDD 门槛仍有缺口，明确记录并补齐必要工作，不直接宣布整体完成。

## 验收计划

1. 验收开始和修复后检查 Unity 编译/Console；执行与最终交付相关的 EditMode、PlayMode 和全部正式关卡参考解法检查，保留实际结果。
2. 从实际 UI 走完 GDD 第 11.4 节作者操作脚本，逐项对应 E01–E12；业务 API 测试不能替代界面证据，独立用户评价与 Agent 操作记录分开。
3. 构建 Windows 非开发 Player，实际完成至少两关；退出重启后检查进度与设置，试听音效和两个 BGM 循环，并验证所有导航、暂停/继续和音量路径。
4. 检查 720p/1080p、窄门/转角/边界、大图俯视和角色/机关识别；在约定机器与场景测量帧率/帧时间及内存，保留方法与结果，不凭主观流畅宣称性能通过。
5. 逐条核对交付清单和可复现证据，区分自动测试、界面操作、独立 Player 交互、性能和独立用户反馈；修复后按影响范围复验。缺失必要验收时保持未完成或受阻状态。
6. 检查最终文档链接、差异及范围，聚焦提交 `[v0.9.0]`，报告最终提交与本地构建入口。发布需后续明确请求。
