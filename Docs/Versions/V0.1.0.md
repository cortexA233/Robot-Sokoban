# v0.1.0 · 文档归类与版本管理

状态：已完成 · 类型：文档 / 工程维护 · 起始提交：`0dd9ca2`。

编制时点：本轮文档整理进行中，用户追加了后续迭代先规划版本的要求；本轮作为追踪起点。后续新迭代必须在实现前登记计划。

## 目标与范围

- 将现行文档按 Gameplay、美术、UI、编辑器、Debug 和工程维护归类，提供统一索引。
- 拆出已有开发阶段记录，配套归档方案、截图和验证 JSON；区分当前状态与历史验收。
- 更新引用、Agent/技能入口、资产清单生成器中的文档路径，保留历史证据的测量结果。
- 在 `AGENTS.md` 写入版本规划规则，建立版本台账，并用提交前缀关联每次实现。

不包含游戏功能、关卡配方、Unity 资源、引擎/包版本或美术源文件修改；不重新执行历史游戏/资产验收，也不发布产品。工作区原有修改和第三方导入继续保留。

## 验收计划

1. 检查所有项目文档、Agent/技能入口的本地链接与章节锚点；确认每份文档可从总索引到达。
2. 解析归档 JSON、路径迁移表及资产清单；核对移动截图的字节、历史测试结果、时间和实测资产哈希保持不变。
3. 检查旧路径只出现在明确保留的历史快照及迁移表中；验证清单生成器语法与新路径，确认 Unity 源码仅变更文档注释。
4. 对比本轮开始时的工作区快照，确认无关文件、关卡配方与用户修改保持原样；审查差异并执行 `git diff --check`。
