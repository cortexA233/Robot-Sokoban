# v0.4.0 · 编辑器易用性与制作发布流程

状态：已规划 · 类型：编辑器 / 作者工具 · 需求：R02、R05 · 策划起始提交：`2a13adb` · 实施起始提交：待开工时记录。

## 目标与范围

- 本版是 [路线图](Roadmap.md) 的第一执行版本，基于现有 v0.3.0 玩法及已提交工具。先整理作者操作，再补齐目录管理，交付完整的“制作→校验→试玩→加入正式目录”路径。
- R02：整理文件/编辑/校验试玩/目录/现场编辑/帮助入口；细分地形、角色与箱子、机关及其现有种类；明确当前画笔、擦除层、朝向、选中对象和未保存状态，按对象显示相关属性。
- R02 追加（2026-09-17）：点击“试玩并录制”时，对当前工作副本执行校验并刷新窗口内的完整错误/警告列表；错误阻止进入试玩，只有警告仍可试玩，无须用户再手动点击一次“校验”。失败反馈采用窗口侧边短时临时提示，显示错误数量和简短原因；具体问题列表持续保留，带坐标的问题继续支持点击定位。提示位置、停留时长和关闭方式在布局实施时细化。
- 选择交互暂不改动，先向用户解释当前“格坐标 + 单个编辑对象”的关系，再由用户决定是否调整。拟讨论方向是显示格内地形/机关/角色或箱子的可读名称、明确标出当前编辑对象，并消除高亮格与属性对象不一致；这些是待定方案，不视为已确定的重做范围。
- 用户追加“选中 A 格箱子后再点 B，格子和对象选择仍停留在 A”的问题。建议方案（待用户决定）：右侧选择对象时明确进入选择模式；点击不同格 B，同步切换格高亮、格内对象列表和属性目标，B 无对象则清空原对象，B 有一个对象则选中它，有叠放对象则默认玩家/箱子优先并提供明确的同格切换按钮。重复点击同一格保留仍有效的当前对象，不暗中循环切换。选择与连续放置模式有持续可见的状态提示，Esc 可回到选择模式；选择行为本身不移动对象、不修改文档或新增编辑撤销。
- R05：提供目录加入、移出与排序，显示关卡结构和参考解法状态；构建前校验正式目录引用、重复 ID 与参考解法是否对应当前内容，错误可定位，不能悄悄跳过坏关卡。
- 同步作者指南；保留 Undo/Redo、原子保存、草稿恢复、旧数据兼容、试玩录制及现场编辑往返。目录移出不删除关卡文件，另存副本以新 ID 重新建立解法证明。
- 开工时细化分类树、控件布局、搜索或快捷入口、目录面板形式；先用现有制作任务比较操作步骤，再落实 UI。常用功能不应因分类细化而变得更难到达。
- 不包含新机关或箱型、玩家 UI 美化、镜头/美术、存档和音频；保留现有正式关卡 ID 与布局。引擎与包版本保持项目约定。

## 验收计划

1. Unity 编译通过，检查 Console；按改动运行作者数据、目录、复制/保存/恢复、参考解法相关 EditMode 检查及试玩桥接的 PlayMode 检查。
2. 从实际编辑器 UI 新建小图，放置两类箱子、两类插槽、门、轨道和转向板，配置来源/方向，完成校验定位、撤销/重做、保存重开和试玩返回；检查现场草稿与正式作者文档隔离。
   - 未手动校验的新草稿、已校验后又产生错误的草稿，直接点击试玩均应展示最新完整错误，保持作者文档并阻止进入 Play Mode；修复后直接点击试玩可以继续，旧错误不残留。
   - 手动校验和试玩前校验共用可见结果；错误侧边提示能被注意到、短时后消失，完整问题列表仍可查看和定位；仅有警告时不阻止试玩。不能只更新底部一句提示或依赖 Console。
   - 若采用上述选择方案，补测 A→B（B 为空格、单对象、箱子叠插槽）、同格切换插槽后再次点击该格、放置画笔中从右侧选择对象再点 B、非法放置之后继续选择及鼠标离开棋盘后释放。二维棋盘与 SceneView 行为一致；没有“格在 B、属性仍指向 A”的状态，纯选择不改变关卡内容或产生编辑撤销。
3. 从 UI 录制或校验解法，加入/排序/移出目录，确认游戏选关随目录变化。隔离验证缺失资源、重复 ID、无效或过期解法确实阻止不合格构建；合法目录可通过。
4. 逐项记录本版覆盖的编辑器要求和实际操作证据，保护原有关卡、解法与草稿；发现本版造成的失败先修复复验，不能留到 v0.9.0。
5. 检查差异、资源 GUID、文档链接与无关工作，更新台账并创建 `[v0.4.0]` 聚焦提交。

## 执行结果与限制

- 当前仍为已规划；本次完成新增需求记录和源码只读核对，尚未修改编辑器代码，未运行 Unity 验收。实施起始提交在实际开工时记录。
- 试玩反馈现状：`PlaytestBridge.Play` 已调用结构校验，但失败只抛出“关卡有校验错误，请点击校验并修复”；窗口将其写入普通提示文字，没有调用用于刷新完整问题列表的 `Validate`。本项需要把校验结果接入可见反馈，保留现有试玩准入约束。
- 选择现状：选择画笔点击格子后，记录格坐标，并按玩家→箱子→插槽→门→转向板的顺序选中该格第一个对象；右侧 `选择 crate_…` / `选择 socket_…` 是互相切换的单选按钮。移动和属性修改作用于当前对象，右键则按擦除层操作。二维符号优先显示玩家/箱子，因而会遮住插槽符号。
- 选择易用性待定项：格高亮不区分格内对象，切换按钮缺少选中态且显示内部 ID；同格对象列表未包含玩家；刷地形/擦除只更新格坐标而不重置当前对象，可能出现高亮格与属性对象不一致。这些是本次代码核对发现，不能写成已修复或已经过实机复现。
- A→B 不切换的源码线索：右侧“选择”按钮只写入 `selectedId`，没有将 `brush` 切回 `Select`；如果仍是实体放置画笔，下一次点击 B 会进入 `document.Place`。B 已有冲突对象时会抛出异常，`selectedId` 保留 A，位于调用末尾的界面刷新也被跳过，从而可能继续显示 A。正常 `Select` 分支本来会更新 B 的格与对象；用户此次实际触发路径尚未在实机复现，实施时需同时检查鼠标笔划结束与重复格过滤，不能仅凭源码线索宣称根因已验证。
- 规划补充检查：三份版本文档的 49 个本地链接有效，版本状态保持“已规划”；本次文档差异检查通过，不涉及 Unity 编译或游戏验收。
