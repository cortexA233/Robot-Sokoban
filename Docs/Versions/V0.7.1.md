# v0.7.1 · 主菜单入口与门—插槽视觉简化

状态：已规划 · 类型：UI / 场景表现修正 · 需求：R10（R01/R03 的后续反馈） · 策划起始提交：`a5e1160` · 实施起始提交：待开工时记录。

## 目标与范围

- 按用户指定版本登记三项反馈：移除主菜单“从第一关开始”；移除受电门上的浮动提示文字；将第 9 关左上插槽的身份边框统一为橙色。
- 基于已经合入 main 的 v0.6.0 UI/存档和 v0.7.0 音效子项整理方案；排期为 v0.7.0 → v0.7.1 → v0.8.0，保留 v0.7.0 的进行中状态与余项。
- 技术依赖为现有主菜单生成/绑定、进度入口和电路表现；v0.7.0 的 BGM、独立音量、图形反馈与试听仍归原版，不并入本版。R01/R03 的已完成记录保持原样，以 R10 跟踪本次后续修正。

### 现状核对

- [用户反馈截图](V0.7.1Reference.png) 对应正式目录第 9 项 [L12](../../Assets/Resources/configs/levels/L12.json)，左上插槽为 `socket_a`，坐标 `(1,7)`，也是通关目标。
- `gate_F`（橙色，位于 `(5,4)`）的唯一来源为 `socket_a`；`gate_D`（蓝色，位于 `(4,3)`）的来源为 `socket_s` 和 `socket_a`，两门均为 Any。`socket_a` 实际同时给两门供电，现有按门分段身份边框因此呈现蓝橙两色。
- [StationCircuitLayout](../../Assets/Scripts/Presentation/StationCircuitLayout.cs) 按稳定门 ID 排序分配样式；[StationCircuitView.AddSocket/AddIdentity](../../Assets/Scripts/Presentation/StationCircuitView.cs) 对每个关联门分别画边框色段。[调色板](../../Assets/Scripts/Presentation/StationCircuitMesh.cs) 的第 0/1 色分别为蓝/橙，对应本关 `gate_D`/`gate_F`。
- 门上的黑底文字由 `StationCircuitView.NewLabel/UpdateGateText` 创建和更新；同类文字也显示 All 条件与占据保开说明。`LateUpdate` 同时借助标签位置判断门的查看焦点，不能把删标签与连线触发当作互不相关的修改。

### 方案

1. **主菜单删除“从第一关开始”。** 从 [MainMenu Prefab](../../Assets/Resources/UI_prefabs/screens/MainMenu.prefab)、[页面绑定](../../Assets/Scripts/UI/MainMenuPage.cs) 和 [生成器](../../Assets/Scripts/Editor/UI/StationUIAssetBuilder.cs) 同步移除 `Content/Actions/NewGame`、点击绑定和显隐分支。按钮列表自然收拢，无禁用按钮或空位；无最近关卡时仍显示“开始游戏”，有有效记录时显示“继续游戏”。重玩首关通过“选择关卡”进入第 1 关；保留暂停/HUD 的“重开本关”、已有成绩、存档重试及现有点击音效。
2. **删除受电门的浮动文字标牌。** 对所有关卡的受电门移除“任一/全部 · 已通电数/总数”及同一标牌中的“占据保开”文字，连同黑底框、引线和仅为排版使用的对象/更新逻辑清理；俯视和第三人称一致。保留门模型、开闭通路图形、供电状态灯、来源状态灯和占据保开图形。将门的按需连线焦点从文字标签迁到门本体/投影区域；俯视指向门或插槽、第三人称靠近时仍能查看线路，继续处理视口和遮挡条件。常规玩家画面不另增文字框，GM 的按需诊断文字不在删除范围。
3. **插槽身份边框使用单一主连接色。** 单门关联沿用该门颜色；一源多门时，优先选择“唯一供电来源就是该插槽”的门作为主关联，并列或没有这种门时按稳定门 ID 排序选定。颜色在断电、通电、撤销、重开、视角切换和重建时保持稳定，不随当前哪扇门通电而切换。该规则在 L12 为 `socket_a` 选择 `gate_F`，使整圈身份边框统一橙色，不保留蓝色分段或蓝色身份点；目标环、插头职责和供电状态灯继续独立表达。其他一源多门插槽复用此规则，无门关联的纯目标保持现有中性标识。

多门关系继续由现有按需连线和门来源状态灯表达：`socket_a → gate_F` 的橙色线路和 `socket_a → gate_D` 的蓝色线路均保留。插槽外框的单色表达主关联，完整供电关系以线路为准；同步当前 GDD/空间站接入说明，避免继续要求“每个关联门的颜色都拼在外框上”。

本版只调整入口与表现，不修改 L12 或其他关卡的 `sourceSocketIds`、Any/All 判定、开门条件、目标职责、布局、稳定 ID 和存档规则；现有解法和内容哈希应保持有效。保留资源 GUID、v0.6.0 悬停修复及 v0.7.0 已合入音效。不包含音频余项、关卡重做、机器人/Blender 资产或完整 UI 改版。

## 验收计划

1. Unity 编译与 Console 检查。主菜单覆盖首次启动、有效最近关卡、存档恢复/写入失败：`NewGame` 控件和绑定均不存在，无空位；开始/继续、选关第 1 关、存档重试、键盘焦点、悬停过渡及点击音效可用，历史成绩不被删除。保护原 Prefab 后在副本验证生成器不会恢复该入口。
2. EditMode 覆盖主关联选色：无关联、单门、多门、唯一来源优先、并列/无唯一来源时的稳定 ID 回退，以及门/来源数组重排。L12 的 `socket_a` 主色来自 `gate_F`，`socket_s` 仍为蓝色，纯目标 `socket_b` 仍为中性标识；连接表仍含原有三条边，关卡 JSON 和内容哈希不变。
3. PlayMode 更新现有文字断言，验证文字框/引线不存在且反复重建无残留；用来源灯、门开闭/供电状态和占据标记验证原语义。覆盖 Any/All、多源交接、能源箱与普通箱、占据保开、撤销/重开；指向/靠近门和插槽仍显示正确的全部关联线路。
4. 以用户截图的 L12 初始局面作前后对照，在 Editor 与独立 Windows Player 的 720p/1080p、俯视/第三人称检查：两门上无文字框；左上插槽身份边框各边统一橙色；蓝门与橙门身份色、纯目标标识保持正确。再覆盖 `socket_a` 通电/断电和被箱子占据，确认边框色不切换，目标与状态仍能辨认。
5. 回放九关参考解法、运行目录/构建门禁及受影响的 UI/电路回归；本次纯表现修改不重写解法哈希或玩家成绩。完成场景查看、页面操作与 Windows 构建后，记录实际结果和工具限制，同步当前维护文档、路线图与台账，创建 `[v0.7.1]` 聚焦提交。
