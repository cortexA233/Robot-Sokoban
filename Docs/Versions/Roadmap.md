# 后续迭代路线图

更新：2026-09-17 · 初始排期基线：`2a13adb` / 玩法 v0.3.0 已封版 · 六版本排期记录：[v0.3.3](V0.3.3.md)；UI 范围补充：[v0.4.1](V0.4.1.md)；默认俯视与 V 键切换补充：[v0.4.2](V0.4.2.md)；初版规划记录见 [v0.3.2](V0.3.2.md)。

这份路线图按用户要求，将九项需求直接拆成 **v0.4.0–v0.9.0 六个执行版本**，并将简单关卡音效与简单 BGM 纳入 R08。版本与工作范围已登记，具体样式、镜头参数等在各版本开工时细化。**v0.4.0 已完成，其余五个版本仍为“已规划”。** 当前实现与缺口见 [实现状态](../ImplementationProgress.md)，实际状态与验收见 [版本台账](README.md)。

## 立项与版本约定

- 已排期工作开工时直接使用下表中的版本计划，补记真实实施起始提交、细化方案与验收，再由“已规划”改为“进行中”。新的独立工作才另行分配版本；文档与配置维护也要规划。
- R01–R09 是稳定的需求索引，版本号负责执行批次；当前下一执行版本为 **v0.5.0**，不是已登记最高编号之后的新版本。六个版本都有独立计划文件，不再等待开工才分配编号。
- 同一版本内按依赖顺序完成子项并共同验收；若实施中发现必须调整拆分，先同步计划、映射与台账。同目标澄清和修复留在活跃版本，已封版的 v0.3.0 和已完成的 v0.3.2 不追加范围。
- 各版本完成后记录实际证据与限制，同步状态、检查差异并创建带 `[vX.Y.Z]` 的聚焦提交。实现、验证受阻和仅完成设计必须分别记录；不能把路线图条目写成已交付。
- 新的明确用户需求可以调整优先顺序；常规编号、计划整理、测试和本地提交自主执行。具体方案影响产品范围时再讨论，不把每一步实施都变成审批。

## 用户提出的四项迭代

### R01 · UI 文案简化与样式优化

**目标：** 缩短理解和操作路径，沿用项目现有简约方向进行适度美化。覆盖主菜单、HUD、选关、暂停、结算、设置，以及下述三项关卡文案配置的移除。编辑器一般易用性改进归 R02；本项包含相关字段和引用的清理，GM 全面改版另定。

- 先列出“必须常显、按需查看、可删除”的信息，统一按钮动词和目标/插槽/供电/门的术语，再调整间距、字号、对齐、对比、按钮状态与视觉层级。
- **用户追加：** 取消关卡标题 `title`、目标提示 `briefing`、完成文案 `completionText` 三项逐关配置，移除关卡编辑器中的“标题”“目标提示”“完成文案”输入框，以及运行时对应的文字显示控件和布局占位。关卡识别使用现有顺序号/稳定 ID；结算保留成绩与操作入口。
- **数据与工具：** 同步现行关卡定义、正式/实验关卡、作者配方和新建模板，处理旧数据的读取兼容或显式迁移；更新目录、试玩、GM 等相关引用，重新验证并保存受影响的参考解法证明。只隐藏控件或把三项文案置空不构成完成。
- HUD 优先保留目标进度、必要操作及关卡状态；按需帮助用于通用操作与规则说明，后续 R07 以移除三项逐关文案后的 UI 为基线。简化时要保留“通电”与“开门”、“能源箱”与“普通箱”的差别。
- 现有第三人称锁定鼠标，俯视可点 HUD；新布局需要同时照顾快捷键和鼠标路径。Prefab 手工布局与重建工具的维护方式应在实现时统一，避免下一次生成覆盖新样式。
- **开工时细化：** 保留文案清单、视觉参考、HUD 信息量、帮助入口、页面改动清单和旧数据迁移方式；本规划不指定新风格稿或全站重做。
- **验收目标：** 三项配置及编辑入口已移除，对应 UI 无残留文案或空白占位，Prefab 重建后不恢复；旧关卡和配方按约定迁移/读取，参考解法、目录与构建校验通过。逐页文案可追溯；720p/1080p 无遮挡或溢出；按钮常态/悬停/选中/禁用可识别；菜单→关卡→暂停→结算→下一关/选关、设置保存和快捷键流程保持可用。

依据：[UI 实现](../UI/UIImplementation.md)。

### R02 · 关卡编辑器易用性与分类

已在 [v0.4.0](V0.4.0.md) 完成。目标是让作者更容易找到对象、理解属性并完成制作。

- 顶栏常用按钮分组，现场工具和示例可折叠；画笔按工具、地形、角色与箱子、机关分类，提供用途提示。
- 当前画笔、擦除层、放置朝向持续显示；格内对象用可读名称和选中态切换。A→B 同步更新格和对象，空格清除旧属性，同格保留当前对象；纯选择不产生编辑撤销。
- 直接试玩刷新当前完整校验结果，有错误则阻止进入；侧边提示约 6 秒消失，完整问题列表和定位入口保留。
- 本轮已核对两类箱子/插槽、门、轨道、转向板、属性/来源、选择、撤销/重做、保存重开、试玩录制及现场隔离；另修复拖刷重做与退出试玩清理问题。

[实际步骤比较、截图和验证](V0.4.0Validation/README.md) 保留范围与方法限制；原有保存、草稿和录制能力继续复用。

### R03 · 场景去文字与门—插槽材质配色

**用户方向：** 删除插头和终点旁常驻的提示文字，用材质颜色区分门与对应插头，减少场景信息堆积。这里“终点”对应计入通关的目标插槽；目标环和插头图形分别表示目标职责与给门供电的职责。

这个方向可行，但现有规则包含一门多来源、一源多门、Any/All，以及“目标同时给门供电”。因此需要先定义配色单位，不能假定每扇门只有一个独占插头。

- **配色候选：** 按门分配连接色，在门框/端口与对应插头上重复；同一插头连多门时显示多个分段色标。也可以沿用来源色、在门上显示多个来源端口，需用实际复杂布局比较后决定。
- **冗余识别建议：** 颜色配合少量形状、纹样或端口图形；不依赖浮动文字承担日常辨认。目标环与插头符号继续可组合，能源箱保持通用外观，避免让人以为箱子也需同色配对。
- **状态分层：** 连接色在断电时仍保留；亮度、填充或状态灯表达电力。Any/All、多来源的当前满足情况，以及“断电但被占据而保开”需要独立图形说明。目标身份在箱子覆盖后仍应从外缘可见。
- **开工时细化：** 调色板、配色单位、图形冗余方案；门旁现有条件文字如何处理；连线是否改为按需显示。插头和目标旁常驻文字的删除是本项方向，其他文字不自动扩大删除范围，也不默认改成另一套常驻小字。
- **验收目标：** 默认游玩画面中上述插头/目标文字消失；720p/1080p、双视角、远近距离、箱子占据和灰阶下能区分目标职责、连接与供电状态；覆盖一源多门、Any/All、多路交接、普通箱占槽、断电保开及撤销/重开；颜色映射在重载与表现重建后稳定。

依据：[现有视觉语义与 v0.2.0 记录](../Art/VisualReadabilityReview.md)、[GDD](../Gameplay/GameDesign.md) 第 4/10 节。R03 将调整当前标牌方案；正式实施时同步当前设计规范，保留 v0.2.0 的历史验收原貌。

### R04 · 第三人称镜头与场景美术综合优化

**目标：** 默认以俯视镜头解谜，按 V 切换到第三人称环绕观察，再按 V 返回俯视；同时缓解小地图中第三人称的逼仄、遮挡和镜头被挤近的问题。

只读基线：当前 FOV 为 55°、默认跟随距离 3.2 m、俯角 25°、目标高度 0.55 m；墙的镜头碰撞盒高 1.54 m。相机避障会参与最终机位计算。**这些参数说明需要联合检查，尚不能证明哪一项是体验问题的主因。**

- **用户追加：** 进入关卡默认使用固定北向的正交俯视镜头，初始居中并完整显示棋盘；覆盖开始游戏、选关、下一关和编辑器试玩入口。V 在俯视与第三人称之间双向切换；俯视释放鼠标以点击 HUD，第三人称锁定鼠标以环绕观察，暂停时释放鼠标。
- 切换保持同一局面、计数与撤销历史；移动、推箱或滑行中的命令继续执行且方向/终点不变，清掉尚未开始的移动输入，新模式需重新按下移动键。功能实施时同步 GDD 第 0.1/3 节及 UI 操作说明。
- 在上述双视角约定下，先在同一关卡、同一路径和窗口尺寸下比较：A 镜头参数调整；B 镜头配合较低墙体/门框；C 镜头配合遮挡墙局部淡出或隐藏。方案数量、具体参数与美术形式在本版本开工时收敛；本版本包含选定方案的实现与验收。
- 镜头侧检查俯角、距离、FOV、跟随目标、阻尼、避障层与碰撞体；美术侧检查墙/门顶的体积、前景遮挡及地图外边缘。降低可见墙高时必须同时审查镜头碰撞体，否则画面变矮但避障仍可能把相机推近。
- 墙体视觉和镜头碰撞的改动要保持规则中的不可通行格；隐藏/淡出不改变关卡解法。先保持现有格长、布局和主角尺寸做对比，扩大地图或整体缩放只有在证据支持且明确纳入范围时再讨论。
- 可比较较高俯角的第三人称跟随镜头，进入关卡的默认视角固定为俯视。先确认资产需要怎样改变，再决定是否进入 Blender 局部修改。
- **开工时细化：** 第三人称希望更贴近角色还是更容易看清棋盘、接受低墙或局部隐藏的程度、可接受的镜头运动与最小观察范围。默认俯视与 V 键双向切换已确定；用户描述的逼仄感作为问题输入，方案效果仍需实机比较。
- **验收目标：** 各关卡入口默认俯视全图，V 可进入第三人称并返回；连续切换和动作中切换不重载关卡或改写局面、计数与撤销历史，进行中的命令方向/终点不变、旧的待执行输入已清除，鼠标/HUD/视角提示与模式一致。记录窄门、贴墙、转角、边界及推箱连续路径，检查镜头穿模、突然拉近/恢复、主体遮挡和可见下一操作格；覆盖 360° 环绕、长按方向锁定、暂停、撤销/重开。记录实际参数与前后对比，自动测试不能代替体验检查。

依据：[CameraRig.cs](../../Assets/Scripts/Presentation/CameraRig.cs)、[BoardView.cs](../../Assets/Scripts/Presentation/BoardView.cs)、[GDD](../Gameplay/GameDesign.md) 第 3 节。与 R03 共用测试机位；镜头未稳定前，材质可探索，但不提前封版其最终屏幕可读性。

## 配套迭代与音频需求

### R05 · 关卡目录管理与发布前校验

已在 [v0.4.0](V0.4.0.md) 完成本地正式目录与构建准备流程。

- 独立目录窗口支持加入、移出、排序、撤销/重做和保存，逐项显示结构与参考解法状态；移出保留源关卡和解法文件。
- 目录窗口与构建回调共用校验，检查引用、重复 ID、结构、当前内容哈希和参考解法回放；必需表现资源缺失也会阻止构建。
- 从新图保存、录制/校验解法、加入/排序，到游戏选关同步已经实际验证；真实坏目录构建被拒绝，合法九关目录构建成功。

验收与剩余交付边界见 [v0.4.0 验收记录](V0.4.0Validation/README.md)。最终 Resources 打包内容筛选归 v0.9.0。

### R06 · 玩家进度与成绩保存

设置已经保存，但正式玩家通关进度与最佳成绩尚未实现。建议先补最小的本地存档闭环。

- **建议范围：** 已完成关卡、最近游玩关卡、最佳步数/推动数及选关展示；首轮“继续”可只返回最近关卡的起点，是否恢复中途局面单独定范围。
- **待定：** 步数与推动数分别记录还是同一次成绩、关卡内容更新后旧成绩如何处理、继续入口语义。现有全关可选的规则保留，解锁门槛需另议。
- **验收目标：** 退出并重新打开独立 Player 后恢复；按稳定关卡 ID 关联，处理移除/改版关卡、损坏存档和首次启动；作者试玩、GM 和现场编辑不污染正式成绩；写入失败可恢复。

### R07 · 新玩家引导与难度节奏复核

原前三关已删除，当前正式目录为 L04–L12；L07/L08 已承担转向教学。建议复核从现有首关开始能否顺利理解规则，**不能仅凭历史关号判定当前首关太难，也不预设必须恢复旧关卡或增加教程关**。

- **建议范围：** 能源箱/普通箱、目标/供电、Any/All、轨道/转向板、撤销和双视角的首次接触；结合 R01 的通用规则帮助和 R03 的图形语义，检查现有九关的信息与难度递进。以 v0.6.0 移除三项逐关文案后的 UI 为基线，不恢复其配置或对应显示控件。
- **待定：** 在现有关卡提供按需提示，还是后续确需独立入门内容；有独立试玩反馈后再决定改图或排序。

### R08 · 简单关卡音效、BGM 与操作反馈

用户已明确要求为关卡增加简单音效与简单 BGM，排入 v0.7.0。现有移动/推动/门动画继续使用；本版补最小音频集合和受阻/完成反馈。

- **音效范围：** 移动/推动、受阻、落位、通电/断电、完成、UI 点击；同一事件去重并限制重复播放，避免长按或连续机关变化造成噪声。
- **BGM 范围：** 首轮一首简单、低干扰、可循环的关卡背景音乐供所有正式关卡共用；同曲切关与重开连续播放，返回主菜单淡出，暂停时降低音乐音量并停止动作音效。曲目数量与这些默认行为需要改变时，在本版本内明确更新计划。
- **音量与反馈：** 保留主音量，增加音乐/音效独立音量并保存，零音量可静音；v0.7.0 负责新增设置控件，沿用 v0.6.0 样式。受阻/完成加入简短图形反馈，复用现有角色锚点，不重做机器人动画。
- **开工时细化：** 音色、音乐风格、素材来源、循环接缝及默认音量。优先复用可随项目分发的素材或简单原创素材，并保留来源说明；首轮不扩展到每关专属配乐或动态分层音乐。
- **验收目标：** 独立 Player 能听到音效与 BGM，循环无明显接缝或叠播；音量、静音和重启恢复生效；暂停/切关/重开无残留旧音效、重复 BGM 或失效引用；撤销不重播已取消动作，关闭声音时状态仍可理解，规则与计数不变。

## 执行边界与排期调整

当前执行顺序固定为 **v0.4.0 → v0.5.0 → v0.6.0 → v0.7.0 → v0.8.0 → v0.9.0**。R01 的术语盘点、R07 的问题收集可以随相关版本积累，但各项最终交付归属以上映射。每轮都先验证本轮完整结果再进入后续范围；最终验收不成为推迟已知故障修复的理由。

若用户后续调整优先级，先同步未开工版本的执行顺序、依赖和范围，再继续工作；已完成版本保持原记录。本轮只完成排期，下一次可直接指定“开始 v0.4.0”，无需重新编号或再列一份需求池。

暂放候选、不占主线版本：GM M4 的可视回放与 Microstep 检查（需要逐步排查复杂关卡时再启用）、更多关卡和新机制。现阶段不自动加入全面资产重做、引擎升级、联网存档、社区或跨平台扩展。

v0.9.0 是完整交付验收版本，不自动升级为 v1.0.0，不创建标签或授权发布。每轮实现按对应计划记录结果；路线图、版本台账和计划共同维护，避免只改一处产生矛盾。
