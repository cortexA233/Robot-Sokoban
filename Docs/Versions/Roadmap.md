## 立项与版本约定

- 已排期工作开工时直接使用下表中的版本计划，补记真实实施起始提交、细化方案与验收，再由“已规划”改为“进行中”。新的独立工作才另行分配版本；文档与配置维护也要规划。
- R01–R14 是稳定的需求索引，版本号负责执行批次；**v0.7.0** 保留进行中状态，用户指定的 **v0.7.1** 已独立完成，新的 **v0.8.0 收尾版本** 已完成。原六个版本、追加修正版及新收尾范围都有独立计划文件，不再等待开工才分配编号。R14 在独立实验分支完成，不代表已合入 main。
- 同一版本内按依赖顺序完成子项并共同验收；若实施中发现必须调整拆分，先同步计划、映射与台账。同目标澄清和修复留在活跃版本，已封版的 v0.3.0 和已完成的 v0.3.2 不追加范围。
- 各版本完成后记录实际证据与限制，同步状态、检查差异并创建带 `[vX.Y.Z]` 的聚焦提交。实现、验证受阻和仅完成设计必须分别记录；不能把路线图条目写成已交付。
- 新的明确用户需求可以调整优先顺序；常规编号、计划整理、测试和本地提交自主执行。具体方案影响产品范围时再讨论，不把每一步实施都变成审批。

## 用户提出的四项迭代

### R01 · UI 文案简化与样式优化

已在 [v0.6.0](V0.6.0.md) 完成。以下保留需求与验收目标；实际实现、证据和工具边界见 [验收记录](V0.6.0Validation/README.md)。

**目标：** 缩短理解和操作路径，沿用项目现有简约方向进行适度美化。覆盖主菜单、HUD、选关、暂停、结算、设置，以及下述三项关卡文案配置的移除。编辑器一般易用性改进归 R02；本项包含相关字段和引用的清理，GM 全面改版另定。

- 先列出“必须常显、按需查看、可删除”的信息，统一按钮动词和目标/插槽/供电/门的术语，再调整间距、字号、对齐、对比、按钮状态与视觉层级。
- **用户追加 · 导航表现：** 主菜单、暂停菜单等页面存在鼠标移入按钮后闪烁一下的反馈。纳入 v0.6.0 的复现、根因验证与修复，并回查选关、设置、结算和 HUD；[初始静态检查](V0.5.2.md) 后，实机复现确认透明黑色同时插值 RGB/alpha 会造成暗闪，已保留透明态悬停 RGB 修复。焦点、完整指针事件、Editor/Player 悬停与生成器副本重建均已检查，见 [v0.6.0 验收](V0.6.0Validation/README.md)。
- **用户追加：** 取消关卡标题 `title`、目标提示 `briefing`、完成文案 `completionText` 三项逐关配置，移除关卡编辑器中的“标题”“目标提示”“完成文案”输入框，以及运行时对应的文字显示控件和布局占位。关卡识别使用现有顺序号/稳定 ID；结算保留成绩与操作入口。
- **数据与工具：** 同步现行关卡定义、正式/实验关卡、作者配方和新建模板，处理旧数据的读取兼容或显式迁移；更新目录、试玩、GM 等相关引用，重新验证并保存受影响的参考解法证明。只隐藏控件或把三项文案置空不构成完成。
- HUD 优先保留目标进度、必要操作及关卡状态；按需帮助用于通用操作与规则说明，后续 R07 以移除三项逐关文案后的 UI 为基线。简化时要保留“通电”与“开门”、“能源箱”与“普通箱”的差别。
- 现有第三人称锁定鼠标，俯视可点 HUD；新布局需要同时照顾快捷键和鼠标路径。Prefab 手工布局与重建工具的维护方式应在实现时统一，避免下一次生成覆盖新样式。
- **本轮取舍：** 沿用浅底/深灰/橙色；HUD 保留关卡序号、目标供电和成绩计数，规则放入按需帮助；旧文案读取兼容丢弃，机制版本与稳定 ID 保留。
- **验收目标：** 三项配置及编辑入口已移除，对应 UI 无残留文案或空白占位，Prefab 重建后不恢复；旧关卡和配方按约定迁移/读取，参考解法、目录与构建校验通过。逐页文案可追溯；720p/1080p 无遮挡或溢出；按钮常态/悬停/选中/禁用可识别；菜单→关卡→暂停→结算→下一关/选关、设置保存和快捷键流程保持可用。
- **导航专项验收：** 主菜单与暂停菜单覆盖默认选中/未选中按钮的移入、停留、移出、点击及连续切换，覆盖键盘→鼠标→键盘、鼠标已位于按钮时开页、设置往返及暂停/转场后的焦点恢复。先建立能捕获原闪烁的复现和完整输入事件回归，再在 Editor/独立 Player、720p/1080p 检查原步骤：渐变完成后持续悬停至少 1 秒稳定，无非预期亮暗跳变、状态往返或焦点抢回，键盘导航、按下/禁用态和点击仍可用；相关页面与生成器重建结果一并检查。

依据：[UI 实现](../UI/UIImplementation.md)。

### R03 · 场景去文字与门—插槽材质配色

已在 [v0.5.0](V0.5.0.md) 完成。以下保留立项依据，实际采用按门配色、分段图形与按需连线；[画面、回归与限制](V0.5.0Validation/README.md) 已记录。

**用户方向：** 删除插头和终点旁常驻的提示文字，用材质颜色区分门与对应插头，减少场景信息堆积。这里“终点”对应计入通关的目标插槽；目标环和插头图形分别表示目标职责与给门供电的职责。

这个方向可行，但现有规则包含一门多来源、一源多门、Any/All，以及“目标同时给门供电”。因此需要先定义配色单位，不能假定每扇门只有一个独占插头。

- **采用配色：** 按稳定门 ID 排序分配连接色，在门框/端口与对应插头上重复；同一插头连多门时显示多个分段色标。门格边缘独立显示各来源的空心/实心状态灯。
- **冗余识别建议：** 颜色配合少量形状、纹样或端口图形；不依赖浮动文字承担日常辨认。目标环与插头符号继续可组合，能源箱保持通用外观，避免让人以为箱子也需同色配对。
- **状态分层：** 连接色在断电时仍保留；亮度、填充或状态灯表达电力。Any/All、多来源的当前满足情况，以及“断电但被占据而保开”需要独立图形说明。目标身份在箱子覆盖后仍应从外缘可见。
- **最终呈现：** 六色配合不同轮廓图形，后续颜色循环补短条。插头和目标旁常驻文字已删除；门保留“任一/全部 · 通电数/总数”与占据保开说明。线路在俯视指向或第三人称靠近时显示，保持断电虚线、通电实线。
- **验收目标：** 默认游玩画面中上述插头/目标文字消失；720p/1080p、双视角、远近距离、箱子占据和灰阶下能区分目标职责、连接与供电状态；覆盖一源多门、Any/All、多路交接、普通箱占槽、断电保开及撤销/重开；颜色映射在重载与表现重建后稳定。

依据：[现有视觉语义与 v0.2.0 记录](../Art/VisualReadabilityReview.md)、[GDD](../Gameplay/GameDesign.md) 第 4/10 节。R03 将调整当前标牌方案；正式实施时同步当前设计规范，保留 v0.2.0 的历史验收原貌。

### R04 · 第三人称镜头与场景美术综合优化

已在 [v0.5.0](V0.5.0.md) 实现默认俯视、V 双向切换及 48°/4.8 m 第三人称初始机位。后续 [v0.5.1](V0.5.1.md) 按用户反馈取消第三人称局部剔除，墙体与门上层始终完整显示；[原三方案比较、连续演示与验收](V0.5.0Validation/README.md) 保留为历史记录。

**目标：** 默认以俯视镜头解谜，按 V 切换到第三人称环绕观察，再按 V 返回俯视；同时缓解小地图中第三人称的逼仄、遮挡和镜头被挤近的问题。

改动前基线：FOV 55°、跟随距离 3.2 m、俯角 25°、目标高度 0.55 m，墙碰撞盒高 1.54 m。L06 同局面的贴墙机位对比确认：仅调参仍被原碰撞盒挤近；局部隐藏并同步缩短该碰撞代理后能够保留观察距离。

- **用户追加：** 进入关卡默认使用固定北向的正交俯视镜头，初始居中并完整显示棋盘；覆盖开始游戏、选关、下一关和编辑器试玩入口。V 在俯视与第三人称之间双向切换；俯视释放鼠标以点击 HUD，第三人称锁定鼠标以环绕观察，暂停时释放鼠标。
- 切换保持同一局面、计数与撤销历史；移动、推箱或滑行中的命令继续执行且方向/终点不变，清掉尚未开始的移动输入，新模式需重新按下移动键。功能实施时同步 GDD 第 0.1/3 节及 UI 操作说明。
- 在上述双视角约定下，先在同一关卡、同一路径和窗口尺寸下比较：A 镜头参数调整；B 镜头配合较低墙体/门框；C 镜头配合遮挡墙局部淡出或隐藏。方案数量、具体参数与美术形式在本版本开工时收敛；本版本包含选定方案的实现与验收。
- 镜头侧检查俯角、距离、FOV、跟随目标、阻尼、避障层与碰撞体；美术侧检查墙/门顶的体积、前景遮挡及地图外边缘。降低可见墙高时必须同时审查镜头碰撞体，否则画面变矮但避障仍可能把相机推近。
- 墙体视觉和镜头碰撞的改动要保持规则中的不可通行格；隐藏/淡出不改变关卡解法。先保持现有格长、布局和主角尺寸做对比，扩大地图或整体缩放只有在证据支持且明确纳入范围时再讨论。
- 可比较较高俯角的第三人称跟随镜头，进入关卡的默认视角固定为俯视。先确认资产需要怎样改变，再决定是否进入 Blender 局部修改。
- **当前取舍：** 按用户反馈，第三人称保留完整墙体和门上层，通过完整碰撞代理避障；不按视线剔除或淡出模型。俯视继续隐藏上层，切回第三人称立即恢复；地图、模型比例和逻辑通行性不变。
- **验收目标：** 各关卡入口默认俯视全图，V 可进入第三人称并返回；连续切换和动作中切换不重载关卡或改写局面、计数与撤销历史，进行中的命令方向/终点不变、旧的待执行输入已清除，鼠标/HUD/视角提示与模式一致。记录窄门、贴墙、转角、边界及推箱连续路径，检查镜头穿模、突然拉近/恢复、主体遮挡和可见下一操作格；覆盖 360° 环绕、长按方向锁定、暂停、撤销/重开。记录实际参数与前后对比，自动测试不能代替体验检查。

依据：[CameraRig.cs](../../Assets/Scripts/Presentation/CameraRig.cs)、[BoardView.cs](../../Assets/Scripts/Presentation/BoardView.cs)、[GDD](../Gameplay/GameDesign.md) 第 3 节。与 R03 共用测试机位；镜头未稳定前，材质可探索，但不提前封版其最终屏幕可读性。
