# v0.6.0 · 简约 UI 与玩家进度

状态：已完成 · 类型：UI / 玩家存档 · 需求：R01、R06 · 策划起始提交：`2a13adb` · 实施起始提交：`06e61c15c6a859350780832cacc5f4868ec86ef0`。

## 目标与范围

- 排期前置：[v0.5.0](V0.5.0.md)，沿用其视觉语义及 v0.4.0 稳定的关卡目录。将文案/样式和进度展示一起落地，避免主菜单、选关、结算重复改版。
- R01：统一主菜单、HUD、选关、暂停、结算、设置的术语、按钮文案、信息层级、间距、字号、对齐与状态样式；减少常驻长说明，保留必要目标/状态和按需帮助入口。
- R01 追加 · 导航表现：检查并修复主菜单、暂停菜单等页面在鼠标移入按钮后短暂闪烁的问题，并回查选关、设置、结算及 HUD 的同类控件。用户怀疑选中态与悬停态换色冲突，当前仅列为待验证原因；先捕获复现，再核对正常/悬停/选中/按下/禁用状态、默认焦点、鼠标与键盘导航切换，以及页面打开和转场恢复时的事件顺序。
- 明确悬停与导航焦点同时存在时的显示规则，保证指针停留时颜色稳定、移入移出过渡连贯、点击与键盘确认有效。检查重复焦点设置、PointerEnter/Exit、射线遮挡和 CanvasGroup 交互切换；按复现证据决定修复，不预先认定仅统一颜色即可解决，也不以禁用键盘导航作为修复。涉及状态样式时同步 Prefab 与生成器。
- R01 追加：取消关卡标题 `title`、目标提示 `briefing`、完成文案 `completionText` 三项逐关配置，移除作者编辑器对应输入框，以及 HUD、选关、暂停、结算等界面中使用这些字段的文字控件和布局占位。关卡识别使用现有顺序号/稳定 ID；结算保留成绩与操作入口。
- 同步关卡定义、正式/实验关卡 JSON、作者配方和新建模板，清理目录、试玩、GM 等相关字段引用。为旧版关卡、配方及草稿制定读取兼容或显式迁移方案；重新回放并保存受影响的参考解法证明，保证目录与构建校验通过。三项配置应实际取消，只隐藏 UI 或清空文案不算完成。
- R06：本地保存完成记录、最近关卡和最佳步数/推动数，在“继续游戏”、选关和结算中使用。首轮按“继续到最近关卡的起点”规划，保持全关可选；中途局面存档与解锁条件不在默认范围。
- 进度以稳定关卡 ID 关联，明确关卡改版后成绩处理；首次启动、缺失/损坏存档和写入失败可以恢复。作者试玩、GM 与现场编辑不能污染正式成绩。
- 保留原主音量、灵敏度和镜头反转设置及旧存储键的兼容。为后续音频设置预留合理布局；音乐/音效的控件与功能由 v0.7.0 一起实现，本版不展示无作用的音频选项。
- 开工时细化保留文案、简约样式参考、HUD 信息量、成绩比较方式、关卡改版策略及旧数据迁移方式；同步 Prefab 与重建入口的维护方式，防止新布局被生成器覆盖。帮助用于通用操作与规则说明，后续 v0.8.0 以移除三项逐关文案后的 UI 为基线。
- 不包含新增关卡、新手引导内容的完整制作、音频接入、GM 全面改版、联网存档或复杂账户系统。

开工方案：沿用浅底、深灰文字与橙色主操作；HUD 保留关卡序号、目标供电、步数/推动数和必要快捷键，通用规则放入按需帮助页。关卡仍保留机制 schemaVersion=1/2/3，读取时兼容并丢弃三项历史文案，写出不再包含它们；现有参考解法须实际回放后重新生成。玩家进度独立保存到 persistentDataPath，按稳定 ID 与规范内容哈希关联；同 ID 内容变化时旧成绩不用于新版，最近关卡可从新版起点继续。最佳成绩按步数优先、推动数次之，记录同一次正式通关；设置沿用原 PlayerPrefs 键。

## 验收计划

1. Unity 编译和 Console 检查；运行受影响的页面/输入、关卡流程和存档检查。覆盖首次启动、正常读写、损坏恢复、写入失败、关卡移除或改版、作者/调试身份隔离。
2. 检查三项配置已从现行数据、作者配方/模板和编辑器输入框中移除；旧关卡、配方及草稿按约定读取/迁移，保存重开与现场编辑可用。重新回放受影响的参考解法并保存证明，运行目录与构建校验；迁移保持稳定 ID 和关卡玩法。
3. 720p/1080p 下实际操作主菜单→关卡→暂停→结算→下一关/选关；确认三项文案及对应控件消失，无空白占位，关卡仍可辨识、结算操作完整。检查文案、溢出、控件状态、快捷键、第三人称鼠标锁定及俯视点击，撤销与过渡仍符合现有契约；在受保护的副本上验证 Prefab 重建不会恢复已移除 UI。
4. 导航闪烁专项：在主菜单、暂停菜单分别覆盖默认选中按钮和其他按钮的移入→停留→移出、按钮间连续移动、点击后继续悬停、键盘导航→鼠标→键盘切换，以及鼠标已在按钮位置时打开页面。覆盖暂停→设置→返回、恢复游戏再暂停和转场后的焦点恢复；复查选关、结算、HUD，包含俯视点击和第三人称打开暂停时的鼠标释放/返回锁定。
5. 修复前建立能捕获原闪烁的复现，记录指针事件、当前焦点和实际渲染颜色的逐帧变化；增加经过真实输入模块或完整指针事件链的针对性 PlayMode 回归，不能仅派发 PointerClick。修复后重跑原步骤及相关 UI 测试，在 720p/1080p 的 Editor 与独立 Player 实际确认：允许预期的平滑换色，但不出现非预期亮暗跳变、状态往返或焦点抢回；渐变完成后持续悬停至少 1 秒颜色稳定，重复操作一致，禁用态、键盘焦点及确认/返回保持可用。检查生成器重建后规则仍成立。
6. 在独立 Player 中完成关卡、退出重启，确认完成标记、最近关卡、成绩和设置恢复；“继续”与页面说明一致。
7. 检查已有存档设置兼容、资源引用、Prefab 重建风险、文档与差异；更新台账并创建 `[v0.6.0]` 聚焦提交。
