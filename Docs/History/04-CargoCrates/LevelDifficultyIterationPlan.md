# 狭窄空间与多箱嵌套：关卡迭代方案

日期：2026-09-16。状态：**原始设计提案与离线验证记录；已实施范围见下方更新。**

实施更新（2026-09-16）：用户已确认实现普通箱，并将全部三张草案追加到原关卡之后。A/B/C 对应 L04/L05/L06，正式顺序采用 L01→L02→L03→L04→L05→L06，覆盖第7节原先的三关候选建议。当前实现及运行验证见 [ImplementationProgress.md](../../ImplementationProgress.md)；下文保留设计阶段的分析与离线证据。

本轮需求：提高部分关卡的推箱解谜深度，加入狭窄空间、多箱之间的顺序依赖，以及无需供电、只参与空间调度的普通箱。“嵌套”指解题依赖，不增加连推、堆叠或拉箱。

配套：[草案布局、阶段快照索引与参考解法](Drafts/NarrowSpaceDrafts.json)。该 JSON 是策划示意数据，不能直接作为运行时关卡或现有编辑器配方导入。

## 1. 调整方向

**优先重做箱子之间的依赖，再压缩房间。** 目标是让玩家考虑“我能站在哪里推”“这个空格下一步归谁用”“哪只箱子需要先移开再回来”。单纯增加箱子数量、墙壁或运输距离，不足以稳定提高解谜质量。

当时基线来自实际 L02、L03 数据和 [GDD 第 5 节](../../Gameplay/GameDesign.md#5-正式关卡方案与可回放布局)；这两关的数据文件已在 [v0.2.1](../../Versions/V0.2.1.md) 删除，原布局仍可查阅 GDD 的历史设计：

| 现有关卡 | 当前结构 | 本次判断 |
|---|---|---|
| L01 | 单箱基础教学，参考解法 8 步 / 3 推 | 保留入门职责；优先解决后两关的深度 |
| L02 | 13×9、两个宽房间、两只能源箱、一段供电交接；参考 32 步 / 16 推 | 借电概念明确，但腾挪空间宽裕，箱子之间的站位竞争较少 |
| L03 | 19×9、三个宽房间、三只能源箱、两段供电交接；参考 68 步 / 28 推 | 扩大了搬运规模，解题结构仍以重复交接为主 |

以上是布局分析，未重新测量玩家通关时间。旧关卡仍可作为机制教学、兼容与参考解法回归样本。

## 2. 普通箱的规则提案

| 属性 | 能源箱 | 普通箱 |
|---|---|---|
| 机器人推动 | 一次一格，只能推一只 | 相同 |
| 占据地板、阻挡玩家和其他箱子 | 是 | 是 |
| 进入目标或辅助插槽 | 可以，并供电 | 可以，只占位置，不供电 |
| 参与完成条件 | 所有目标插槽被能源箱供电 | 不要求到达目标，也不要求归位 |
| 占据断电门 | 按现有防夹规则保持门开 | 相同；占门不等于供电 |
| 低摩擦、撤销、重开 | 沿用现有规则 | 相同 |
| 视觉 | 发光芯、能源符号 | 无发光芯、货箱交叉筋或货物标记 |

建议玩家名称用“普通箱”或“货箱”，数据名称可用 `Cargo`。不使用“障碍物”暗示它不可移动。类型同时用形状/标记和色彩表达，两种视角都能辨认。

补充边界：

- 能源箱 A/B 与目标 a/b 的字母只是本草案的讲解标记，**没有指定配对规则**。
- 普通箱进入不会再用到的死角可以是正确终局；不能把“所有箱子还能移动”作为通关要求。
- 不可移动的固定障碍继续用墙或现有地形表达，不为本次增加第三种箱子。
- 正式草案先不叠加低摩擦；类型加入后仍回归两类箱子的轨道规则。

## 3. 可复用的空间谜题结构

1. **反向让位**：能源箱先推离目标方向，腾出普通箱退让的位置，再把能源箱推回来。
2. **站位争夺**：普通箱虽然离开通道，却占着玩家下一次推箱必须站的格子，需要再次调整。
3. **先深后浅**：目标放在同一条窄巷，先把一只能源箱送到深处，最后才封住入口目标。
4. **侧袋与绕行口**：一格宽的通道配一个停车侧袋和一条绕行路，玩家必须看出从哪一侧推。
5. **空间动作兼任供电动作**：能源箱借位时恰好进入辅助插槽；另一只能源箱接替供电后才能回收。

“狭窄”主要放在关键连接处。转弯和换手处保留必要的 2×2 或 2×3 空间，外围保留能改变推箱方向的绕行路。全部压成单向长廊会减少选择，也可能直接造成死局。

## 4. 草案 A：借一格

用途：普通箱与反向让位的小型教学；7×7，1 能源箱 + 1 普通箱，1 目标，无门。初次试玩目标约 2–4 分钟，待实测。

共同图例：`#` 墙，`.` 地板，`P` 玩家，`A/B` 能源箱，`X/Y` 普通箱，`a/b` 目标插槽，`s` 辅助插槽，`D` 门。文字图上北下南，坐标原点在左下，包含外围墙。

```text
#######
###a###
#....##
#.#X.##
#..A.##
##P..##
#######
```

初始：P `(2,1)`；A `(3,2)`；X `(3,3)`；a `(3,5)`。

**核心依赖：A 让位 → X 下移 → A 回中线 → X 再让位 → A 上行。**

| 阶段 | 推动安排 | 设计作用 |
|---|---|---|
| 1 | A 向西到 `(2,2)` | 先做看似远离目标的动作，腾出 X 的退路 |
| 2 | 绕到 X 北侧，X 向南两格到 `(3,1)` | 通道腾空，但关键站位还未释放 |
| 3 | 从 A 西侧把它推回 `(3,2)` | 复用此前让出的中线位置 |
| 4 | 从 X 西侧把它向东推到 `(4,1)` | 机器人进入 `(3,1)`，取得推 A 的站位 |
| 5 | A 向北三格进入 a | 普通箱留在角落也可完成 |

这里 X 不是一次清走的杂物：它先借用未来的推箱站位，随后必须再次让开。教学提示按需给出：“普通箱不供电，但可以挪开”“推动之前，先找机器人站的位置”。

参考解法：`EENWENNWSSNNWWSSESENNN`，**22 步 / 8 推**。

## 5. 草案 B：三箱锁喉

用途：纯空间嵌套中阶关或供电版的对照原型；7×8，2 能源箱 + 2 普通箱，2 目标，无门。初次试玩目标约 4–7 分钟，待实测。

```text
#######
###a###
###b#.#
#P.B.X#
#.#Y#.#
#..A..#
#.....#
#######
```

初始：P `(1,4)`；A `(3,2)`、B `(3,4)`；X `(5,4)`、Y `(3,3)`；a `(3,6)`、b `(3,5)`。

**核心依赖：A 让出退路 → X 打开绕行口 → B 让出上侧站位 → Y 下移 → A/Y 再换位 → 深处目标 → 浅处目标。**

| 阶段 | 推动安排 | 设计作用 |
|---|---|---|
| 1 | A 向东到 `(4,2)` | 腾出 Y 的下移位置 |
| 2 | X 向北到 `(5,5)` | 打开右侧绕行口，机器人可以站到 B 右侧 |
| 3 | B 向西到 `(2,4)`；Y 向南两格到 `(3,1)` | B 先离开正对目标的中线，才能取得推动 Y 的站位 |
| 4 | A 向西回到 `(3,2)`；Y 向西到 `(2,1)` | 复用中线，同时释放 A 后方的玩家站位 |
| 5 | A 向北四格到 a | 先把箱子送至最深处 |
| 6 | B 向东回中线，再向北一格到 b | 最后封住浅处目标 |

侧袋 `(5,5)` 可以作为 X 的永久停车位；Y 使用的 `(3,1)` 则只能临时停车。两种普通箱用途不同，且都不可省略。

应观察的误解：试图连推 B/Y/A；只移走 Y 一格就回送 A；以为能源箱必须一直靠近目标。提示优先指向“站位”和“让位”，不要直接列方向答案。

参考解法：`SSEESEENNNWWSSNNEESSWSWNNNNSSSWWNNEWSSEENN`，**42 步 / 13 推**。

## 6. 草案 C：先过箱，再交电

用途：保留本项目供电特色的后期综合关；7×9，2 能源箱 + 2 普通箱，2 目标、1 辅助插槽、1 门。初次试玩目标约 6–10 分钟，待实测。

```text
#######
###a###
###b#.#
###D#.#
#P.B.X#
#.#Y#.#
#..As.#
#.....#
#######
```

初始：P `(1,4)`；A `(3,2)`、B `(3,4)`；X `(5,4)`、Y `(3,3)`；s `(4,2)`；a `(3,7)`、b `(3,6)`；D `(3,5)`。

**门连接：D = Any(s, a)。浅处 b 不为门供电。**

| 阶段 | 推动安排 | 设计作用 |
|---|---|---|
| 1 | A 向东进入 s | 同一次让位既清空中线，又打开门 |
| 2 | X 北移进侧袋；B 西移借位；Y 南移两格 | 拆开窄道里的多箱堵塞 |
| 3 | B 回中线，向北三格到 a | 先让 B 穿门，并由深处目标接替供电 |
| 4 | A 离开 s，向西回中线；Y 再向西让位 | 回收临时能源箱，门继续由 a 供电 |
| 5 | A 向北四格进入 b | 目标全部通电，普通箱和 s 无需归位 |

与 B 的参考路线相比，主要变化是**先送上方 B，再回收下方 A**。B/C 故意共享主要骨架，便于比较“只加供电是否产生新的规划问题”；不能把复用骨架本身算成两套全新的谜题结构。

参考解法：`SSEESEENNNWWSSWWNNEWSSEENNNNSSEESSWSWNNNN`，**41 步 / 15 推**。步数少于 B 只是这条路线绕行较少，不是难度排名。

现有门规则允许一个合法变体：B 先停在门格撑门，提前取回 A，再将 B 送到 a。离线检查也找到了该路线，并保存在配套 JSON。允许这种系统性解法；本次不为“强制按策划顺序”改门规则。独立枚举仍确认：断开 s 的供电来源后，本布局无解，辅助插槽并非摆设。

## 7. 建议的迭代顺序

### 第一轮：两种箱子贯通最小制作流程

先实现普通箱，使用 A 作为小型验收图。完成“编辑器放置两类箱子 → 保存/打开 → 试玩 → 撤销/重开 → 录制/回放”，再扩大关卡制作。

当前并非只需增加几只箱子：现有规则已经允许箱子数多于目标数，但所有箱子都会供电。必须让占格和供电分别判定。

| 涉及位置 | 建议改动 |
|---|---|
| [LevelDefinition.cs](../../../Assets/Scripts/Gameplay/Domain/LevelDefinition.cs) | CrateDefinition 增加稳定的类型字段，至少 Energy/Cargo；箱子 ID 保持不变 |
| [RuleEngine.cs](../../../Assets/Scripts/Gameplay/Domain/RuleEngine.cs) | 阻挡/门占据使用所有箱子；插槽通电与完成只使用能源箱；保留每个 Microstep 重算与占门防夹 |
| [LevelValidator.cs](../../../Assets/Scripts/Gameplay/Domain/LevelValidator.cs) | “能源箱数 ≥ 目标数”；拒绝未知类型；修正开局完成检查；普通箱死角仅作设计提示，不能推断整关无解 |
| [LevelJson.cs](../../../Assets/Scripts/Gameplay/LevelFlow/LevelJson.cs) | 显式读取 v1 并将其箱子归为 Energy；新类型文件建议写 schemaVersion=2；类型进入内容哈希 |
| [LevelDocument.cs](../../../Assets/Scripts/Editor/LevelEditor/LevelDocument.cs)、[LevelEditorWindow.cs](../../../Assets/Scripts/Editor/LevelEditor/LevelEditorWindow.cs) | 能源箱/普通箱两种画笔与可编辑类型属性；复制、撤销、草稿恢复、试玩快照、配方导入均保留类型 |
| [BoardView.cs](../../../Assets/Scripts/Presentation/BoardView.cs) | 两种箱子有可辨识形状/符号；普通箱压在插槽上仍显示未通电；HUD 只统计目标供电 |

**兼容细节：** 当前 LevelJson 对每个字段做严格形状校验，新增字段不会自动获得安全的旧数据兼容。应按原始 schema 做显式迁移，再走新结构校验；不要放宽所有未知/缺失字段。迁移或新增类型会改变内容哈希，旧参考路线应重新回放后绑定，不能直接继承通过标记。

### 第二轮：先验空间，再合供电

使用现有编辑器制作 B，确认绕行、站位和普通箱用途；在同骨架上制作 C，验证接替供电与回收。这能定位难度究竟来自空间调度还是供电理解。

- 每个关键转弯检查“箱子目的格”和“玩家发力格”；两者缺一即不能完成该推。
- 每只普通箱都回答：它阻挡什么、何时挪开、停在哪里、之后是否需要再动。
- 记录参考解法与关键局面；编辑器验证/共享内核回放通过后，再加入正式目录。
- 不把本次离线模型接成产品内自动求解器，也不绕过既有作者工具手写正式 JSON。

### 第三轮：调整正式关卡与难度曲线

建议先采用 **现有 L01 → A → C** 作为三关候选组合：基础移动与供电、普通箱和让位、四箱嵌套与借电回收。B 保留为 C 的空间对照图及候补挑战关，不默认新增正式关数。

若从 A 到 C 的实际跳跃过大，再将 B 作为中间练习，形成四关路线；或先减轻 C 的 X 绕行阻挡。是否扩为四关由这轮试玩结果决定。不要同时把新手关改成高难谜题。

旧 L02/L03 的稳定 ID 与历史成绩需要单独处理：替换布局时明确关卡身份/成绩版本策略，防止旧通关记录直接套到新布局。旧作者数据与解法保留为回归样本；正式目录仅在新关验证完成后更新。

## 8. 验证与调难度标准

本次已经完成：

- 三张草案逐指令离线回放合法，并达到全部目标供电；参考路线计数分别为 22/8、42/13、41/15（移动/推动），不宣称最优。
- 第二份按单步命令枚举的模型复核了路线和终局；固定每只普通箱分别搜索至状态耗尽，均无解。配套 JSON 保存了各搜索的状态数量。
- C 断开辅助插槽 s 后搜索耗尽仍无解；合法的门占据变体也保留。

这些结果证明的是**草案在拟定规则下有解，普通箱与辅助电源有必要作用**，不等同于 Unity 测试通过，也不证明解法唯一或难度合适。

实施时的必要检查：

1. 规则：普通箱占辅助/目标插槽不供电；足够总箱数但能源不足时报错；能源箱正常开门/完成；两种箱子都不能连推。
2. 状态：普通箱占门防夹，离开后正确关闭；撤销/重开恢复位置、供电和计数；两种箱子的低摩擦规则一致。
3. 作者工具：v1 读取、v2 保存往返、画笔/类型编辑/复制/撤销/草稿恢复；改箱子类型后参考解法失效并可重新验证。
4. 三张草案正式编辑器制作与共享内核回放；有脚本变更时等 Unity 编译结束并检查 Console，按影响范围运行 EditMode/PlayMode。
5. 人工/界面试玩：单格通道、转角、门格和贴墙推动时，两种视角都能看清角色、箱型、插槽；遮挡不能成为谜题难度来源。

试玩记录重点是第一次卡住的位置、错误计划、撤销发生的阶段、提示前后是否理解和重复搬运感。参考推动数只用于比较路线，不能代替难度判断。

- 太简单：收紧一个关键站位或停车位，增加一次有意义的回收；避免只延长运输距离。
- 太难：增加一格绕行/换手空间、明确箱型与连线，或拆出前置练习；每次只改一个约束以便比较。
- 死锁反馈：能源箱进入明显固定死角可提示撤销；普通箱停入侧袋/角落可能正是正确解法。动态多箱死锁仍需解法检查与试玩，不能只靠静态校验判定。

## 9. 后续扩展草图

完成上述三张原型后，再考虑以下两种新结构；目前只有设计意图，没有经过布局可解性验证：

- **共享停车位**：两只普通箱先后借用同一个侧袋，侧袋中的箱子必须被重新取出，才能为下一只箱子让位。重点验证侧袋后的推箱站位，避免做成只能推入不能推出的死角。
- **目标也是道路**：第一只能源箱提前占据目标会堵住另一只箱子的过路/换手位，需要暂时移出目标，待深处运输完成后归位。保留目标箱可挪走的现有规则，不新增机关类型。

两者适合作为独立后续关卡，不在当前供电综合关里继续叠加，以免一次原型同时承担过多新理解负担。
